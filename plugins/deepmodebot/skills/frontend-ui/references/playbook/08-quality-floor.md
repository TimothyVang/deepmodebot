## 8. Quality floor (always, unannounced)
- Responsive down to mobile. Visible keyboard focus. Reduced motion respected. Contrast at WCAG AA.
- Accessible names on icon buttons and inputs. 44 px minimum touch hit areas. Preserve user input through errors.
- Design every reachable state: loading, empty, sparse, populated, validation, error, permission, disabled, optimistic, stale, destructive, responsive.
- No nested modals (exception: discard-changes confirm over a form dialog). Prefer inline disclosure to modals. Radios over select for 2–5 options; combobox only when list needs search.
- **Focus and composite widgets:**
  - Composite widgets (toolbar, tabs, listbox, grid, tree) have one tab stop with arrow keys inside.
  - Focus never falls to `body`: after a delete, the next item; after a close, the opener.
  - Focus looks different from selection. Disabled items inside composites stay focusable via `aria-disabled`. No positive `tabindex`.
  - **Universal icon tooltips & desktop cursor discipline (`icRjQePEa_A`, 11:40–12:38, 18:18):** every icon button and non-obvious status indicator carries a tooltip with its action name + keyboard chord (`Go to pulse · G then P`), wired via `aria-labelledby`/`aria-describedby` on interactive triggers only. Desktop **Operate** apps default standard buttons/rows to the OS arrow cursor (`cursor: default`, optional user preference for `pointer`) and offer a preference to keep animated GIFs/emojis static until hover. Tab state lives in the URL.
  - **Shortcuts:** avoid modifier + Tab / Enter / Space / Escape. Every shortcut target is also reachable by navigation (⌘K needs a visible trigger). Support chorded navigation (`G then P`, `M then B`) without hijacking text inputs, and distinguish tap-toggle from hold-key quasimodes (`05-motion.md`).
- **Data tables:** use `<table>` unless cells are interactive (then ARIA grid). Right-align comparable numbers; start-align IDs; never center text. Empty state replaces the whole table, headers included.
- **Panes and scrolling:** panes work at 320–360 px and cap content width on wide windows. A scroll stays with the region where it started (hovered side pane never steals wheel from a streaming thread).
- **Sensitive content:** blurred when backgrounded. No telemetry without consent.
- **Accessibility (verified in accessibility tree):**
  - Check role, name and state on every interactive element; do a screen-reader pass when semantics change.
  - Name order: visible text → `<label>` / native attribute → `aria-labelledby` → `aria-label` last. No `title` (except `iframe`). Decorative icons are `aria-hidden`.
  - Custom checkboxes/radios/switches keep native input positioned over the visual at hit-area size with `opacity: 0` (never visually-hidden/off-canvas, which breaks touch exploration).
  - Disclosures expose `aria-expanded` (or native `<details>`/popover). Hover/focus content must be dismissible and hoverable (WCAG 1.4.13).
  - Popover != modal. Anything with a backdrop is a dialog: trap focus, inert background, return focus to opener.
- **AI is optional:** core task works with AI off; UI discloses when data leaves the device. External links carry icon + destination label; regulated steps (payment, identity) hand off explicitly.
- **Focus after thread changes:** deleting moves focus to previous item; creating moves it to composer/first control. Repeated row buttons named `"Manage: {title}"`; state goes in ARIA, never the name.
- **Agent-surface acceptance checks:**
  - Refreshing mid-stream or going offline/online resumes with no lost or duplicated tokens.
  - A second tab mirrors the in-flight run, and Stop from another tab works.
  - Running each generative-UI request 3–4 times produces the same layout and labels.
- **Streaming performance:** never hold thread state in one root context value (use per-message subscriptions). Virtualize long threads, enable React Compiler (or fine-grained reactivity), park hidden panels with `<Activity>`, use transitions/optimistic updates for non-urgent work.
- **Worst-case stress test:** long names, 1-letter names, huge counts, empty lists. Decide per field whether text wraps, end-truncates, middle-truncates (filenames/emails), or clamps. Never truncate numbers. `min-w-0` on flex children.
- **Forms:**
  - Clickable labels; `autocomplete` + right `type`/`inputmode`; inputs `>= 16 px` on mobile.
  - Never block paste. Keep submit enabled until request starts (in-place settings may disable Save until dirty; never for validation).
  - Validate on blur, clear error on focus. Single field focuses the errored field; multi-field submit focuses a linked top error summary. Warn on unsaved changes. Multi-step forms validate per step, keep later answers on Back, end with review.
- **Feedback next to trigger:** Copy confirms with inline checkmark (not toast); optimistic updates roll back on failure; async messages use `aria-live="polite"`; URL reflects UI state.
- **Mobile baseline before first component:** `viewport-fit=cover`, `interactive-widget=resizes-content`, per-scheme `theme-color`, zero horizontal overflow (`scrollWidth <= innerWidth`) at `390 px`, `touch-action: manipulation`, `100dvh`, `env(safe-area-inset-bottom)` on sticky CTAs, native Camera/Photos/Files pickers instead of desktop dropzones, `overscroll-behavior` only under `(pointer: fine)` to preserve pull-to-refresh. Keep cached content visible offline (`Offline · Updated 4m ago`) and never hide/low-contrast paywall `×` buttons.
- **Native ports:** 48 dp Android, 60 pt visionOS, 66 pt tvOS (44 px web); body text 13 pt macOS, 14 epx Windows; Wear OS black backgrounds allowed.
