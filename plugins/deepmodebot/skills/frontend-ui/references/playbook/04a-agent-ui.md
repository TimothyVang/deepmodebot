## 4a. Agent UI (chat and agent-console surfaces)
For React apps, run `npx shadcn@latest add message-scroller message bubble attachment marker trace code-block` or start from **`shadcn-ui/chatbot-template`** (for SvelteKit — `skill://deep-stack`'s default — port the same contracts onto native primitives). **AI Elements (`elements.ai-sdk.dev`) is deprecated**; its patterns live in shadcn/ui.

### Core chat & trace contracts
- **Thread:** `MessageScroller` (`scrollAnchor` = user turn; `autoScroll` yields immediately on user scroll-up; `MessageScrollerButton` jumps to latest; once a streamed reply exceeds viewport, keep its *start* in view). Never hand-roll a stick-to-bottom div.
- **Turn:** `Message` (`align="end"` = user) + `Bubble` variants. Agent avatar uses a non-circle shape (square/hexagon); people stay circles.
- **Agent activity:** one `TraceLine` per action inside one `Trace` per run of steps between text blocks; tool row starts plain until output exists, then `TraceCollapsible` with `CodeBlock`. Never hand-roll `"Thinking..."` collapsibles.
- **Status words:** map SDK states explicitly (`Running` → `Ran` / `Failed to run`; `Thinking` → `Thought`); name actual work without anthropomorphism; show explicit states (`queued · running · waiting for approval · error · retried · completed`); collapse finished runs to one summary line (`"Ran 14 tools · 2m 10s"`).
- **Tool states (`switch (part.state)`):** `input-streaming`/`input-available` → Running; `approval-requested` → approval prompt; `approval-responded` → Running/Denied; `output-available` → Ran; `output-error` → Failed to run; `output-denied` → **neutral** `"Denied …"` (user choice != red error); `preliminary: true` → still Running. Subagents render as one line with nested Trace, model/tool badges, and elapsed time. Sources & message actions appear after streaming; Retry only on last assistant message while idle.
- **Dividers, attachments & prompt box:** `Marker` for checkpoints/system notes; `Attachment` wired to `idle → uploading → processing → done / error`; `InputGroup` with pickers whose collapsed trigger displays the active value (`Select` or `DropdownMenuRadioGroup` for model & effort), labeled icons, separate Attach/Focus controls, 3–6 ranked suggestion chips (`ul > li > button`), and cost/token estimate beside Send for expensive runs.
- **Message actions & citations:** 3+ actions use ARIA toolbar (one tab stop, arrow keys); hover-revealed actions stay keyboard-reachable. Citations scale by depth (hover quote → inline link → side panel); context usage uses `HoverCard` + `Progress`.
- **Streaming Markdown:** use a syntax-healing renderer (`Streamdown` or `remend`), `animated` (150 ms fade) + `caret="block"` only on last streaming message, `allowedImagePrefixes` + `allowDataImages: false` (prevents prompt-injection exfil), sanitize enabled, memoized per block, throttled updates, never fake-stream real output.
- **Composer while running:** **Stop always visible beside a working Send** (mid-run messages steer). Stop calls a **server stop endpoint** saving partial text (`"Stopped by you"` + Continue / Discard); a dropped connection reconnects (`vercel/resumable-stream` MIT for serverless SSE resumption without sticky load balancers) and never acts as a stop. Optional `"Answer now"` skips remaining reasoning.
- **Idle composer, driving surfaces & memory:** capability chips + role templates + `"/ for skills"`; persistent banner/border with Stop / Ask before acting / Notify me when an agent drives a browser/canvas; transparent memory inspector with delete, `"Saved to memory"` chip + Undo, and explicit temporary mode.

### Generative UI, cards & artifacts
- **Answer format ladder:** Markdown by default → schema-validated typed component spec (`vercel-labs/json-render` Apache-2.0 `defineCatalog` + Zod props/actions + `defineRegistry` for React/Svelte 5/Vue/Mobile/MCP Apps, or deepmodebot's A2UI `gen_ui.py`; same layout on repeated runs, fallback to Markdown for unknown types, render *after* exploring, never `eval`/raw code) → sandboxed widget only for calculations/games. Rendered data stays in model context; clicks write back semantic state; follow-up prose points to widgets instead of repeating them.
- **Tool-result cards in thread:** max 2 actions (1 primary), 4–5 data points, no menus/modals/tabs/inner scrollers, never duplicate chat input inside a card. Carousels hold 3–8 items (1–2 render as single cards). Expand opens a side panel/fullscreen. Every widget owns loading/disabled/success/error-with-recovery states.
- **Third-party UI (MCP Apps / partner HTML):** sandboxed iframe only, restrictive default CSP, logged `postMessage`, visible `"From {server}"` boundary, host theme via CSS variables, tool calls go through approval ladder.
- **Artifacts & structured edits:** long outputs live in a versioned side panel (agent versions vs manual edits, diffable). Agent edits to structured data land as **pending** with an AI toggletip marker + Accept / Undo (`"Revert to agent value"` after human edit). Clarifying questions render as a sticky `Questionnaire` card above composer, never numbered prose. Regenerate preserves versions (`"2 / 3"`) and `"Branch from here"`.

### Approvals, wait ladder & delegation
- **Approval ladder (prompt *outside* Trace, `Item` + `ItemActions`, collapses once answered):**
  1. Read-only / cheap → runs unprompted (auto-approved line cites policy reason).
  2. Moderate write → inline proposal naming **target, effect, reversibility, evidence** + dry-run preview; options: Approve · Reject (with reason) · Edit args · Respond instead; scoped grants (`allow once / workspace / always`) state scope before commit.
  3. Severe / irreversible (including indirect bulk config deletes) → blocking dialog with type-to-confirm; initial focus on least destructive button.
- **Approval lifecycle:** one decision per prompt; Cancelled/Expired != Deny; wait for server ack before disabling; restore pending approvals after reload; server-verified (free text never authorizes); never `"Approve all"` on a large diff; track approved-then-edited as hidden rejection; warn `>= 20 s` before timeout expiry (WCAG 2.2.1).
- **Plan cards:** numbered plan + estimated duration/cost + scope + explicit hand-back points + exits (**Proceed · Edit plan · I'll do it myself**); flag divergence if execution drifts.
- **Wait ladder:** nothing `< 1 s`; spinners/skeletons after `300–1000 ms`; indeterminate `1–3 s`; determinate `3–10 s`; `> 10 s` background task with notification. First feedback `< 100 ms`. Collapse traces on success, expand on failure. Announce `"Working…"` to screen readers every ~5 s via polite live region. Show deletions in place; every automatic write offers Undo; show High/Med/Low confidence instead of raw percentages.
- **Delegated & background work:** persistent panels via `<Activity>` (preserves scroll/state); task list + attention queue (`All / Awaiting / Working / Idle`) with one shortcut to next awaiting item; review packages with visual before/after; user can always take over; audit log with actor badge, timestamp, Undo window, and `"Why: you allowed X"`.
- **Non-chat surfaces:** match capability to surface (Invisible pre-work, Ambient field markers, Inline selection/code transforms, Conversational only for exploring/building). Proactive help is specific and 1-click revertible. Replace blank open-ended domain AI prompt boxes with **example-driven suggested triggers** (`Auto Label` > blank `Autopilot`) so capability boundaries are visible up front.
- **Multi-session workspace entities & AI diff review (Linear patterns):** model concurrent agents as living workspace rows (`waiting for input · in progress · done`) alongside projects/inbox or in a multi-tab bar, surface inline document edits as compact change cards (`summary + Show changes + Undo`), filter automated bot comments separately from human threads, and render multi-file agent diffs as **thematic intent Guides (`1 of N`)** with a **Meaningful-LOC** header badge (`Meaningful code +X -Y · Total +A -B`) separating core code from tests, lockfiles, and generated files.
- **Identity & safety:** badge every agent-authored artifact, show responsible human on delegated work, sanitize *accumulated* stream with DOMPurify (stop rendering if anything is stripped), and append DOM nodes rather than rewriting `innerHTML` per chunk.
