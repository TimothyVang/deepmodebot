## 9. Steering agents (meta)
- Always-loaded `AGENTS.md` rules trigger more reliably than optional skills. Keep `AGENTS.md` short (~200 lines max per `skill://agent-harnesses/references/delegation-efficiency.md`): inline only universal invariants and route detailed workflows to skills.
- "Explore the project first, then load the skill" works better than "MUST invoke the skill first".
- Write observable rules ("Destructive CTAs use Verb + Noun"), not adjectives ("clean", "polished").
- Criteria wording steers the look: words like "museum quality" pull every design toward one style.
- When a rule is mechanically checkable, make it a lint rule rather than more prose.
- **Prompt with vocabulary:** name effects (pop-in, stagger, morph, rubber-band, origin-aware) and moves (bolder, quieter, distill, polish). Narrow each request to one section and add a feel constraint ("count up, fast and professional").
- Package house effects as parameterized skills (effect, intensity, personality) and improve them after each use.
- If a project defines heavy explicit-only UI skills (for example animation review, library selection, or UI prototyping in its own `.claude/skills/` or `.agents/skills/` — not bundled in deepmodebot), load them by path so names like `prototype` do not collide with user-level skills.
- **Steer design revisions with named verbs** that have project-specific meanings (bolder = hierarchy, scale and type, never gradients, glass or neon; harden = devices, edge cases, performance). No auto mode: a human chooses each steer.
- **Use shapeof.ai pattern names as shared vocabulary** in prompts ("Action Plan", "Stream of Thought: plan / execution / evidence", "Sample response before Auto-fill").
- **One flat accent means "agent acting now"** (§6a): never a gradient, never on idle UI. Brand color only on the primary CTA and badges; status colors only for operational status.
- **Extract design language from screenshots before prompting:** feed 1+ reference screenshots and ask for a 5–6 sentence design-system spec covering color palette, typography hierarchy, card border treatment, spacing density, and aesthetic mood; translate hex approximations into OKLCH role tokens (§6a) in the build prompt.
- **Target exact DOM elements instead of blind pixel chat:** never prompt `"add 8px padding to the second card on the left"`. Inspect the exact DOM selector/box model and specify structural proportions (`"this container takes 70% width; rebalance siblings"`).
- **Steer logic-preserving Design Variations & Annotate decluttering:** when restyling a working app, freeze state/forms/handlers and request full CSS/layout candidates along concrete axes (*Precision Workbench*, *Warm Editorial*, *High-Density Swiss*). To fix clutter or overlaps, visually circle targets on a screenshot and prompt `"Remove all circled elements"` rather than describing coordinates in prose.
