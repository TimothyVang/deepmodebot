# no-reward-hacking

Group: verification. When: designing checks, iterating against a metric, generating 3D/ML/UI/solver artifacts, or declaring a gate passed.
- **Rule.** Satisfy the operator's true goal rather than gaming the proxy metric (Goodhart's Law: once a scalar measure becomes the optimization target, cheap shortcuts score 100% while failing the real requirement).
- **Freeze the oracle.** Builders never weaken their own tests, relax numeric assertions, add unconditional `.skip`, zero out similarity/fidelity bounds (`--min-iou 0`), or disable reference comparisons. Lock gate scripts, reference files, and positive minimum thresholds before iterating (`assets/reward-guard/reward_guard.py lock-contract`).
- **Prove build provenance.** Scalar geometry, schema, or exit-code checks cannot tell a sculpted/solved output from glued-on procedural primitives (`create_cube`, `create_cone`) or hardcoded fixtures. Require a cryptographic provenance receipt (`job_id`/`prompt_id`, approved upstream producer, SHA-256 of reference inputs and delivered artifact via `reward_guard.py record-provenance`).
- **Independent semantic & perceptual judge.** Pair automated gates with a clean-context read-only critic (`reviewer` or perceptual vision judge, `reward_guard.py record-judge`) comparing the rendered or runtime output side-by-side against the original reference and intent, explicitly auditing whether the result fulfills the real goal or substitutes programmer blocks and metric shortcuts.
- **Anti-patterns.** Passing `--min-iou 0` or `--skip-reference` so a gate prints `PASS`; lowering `>=` bounds or raising error tolerances in diffs; substituting local box/cone primitives for upstream 3D/ML generation; treating green unit/geometry gates as completion without side-by-side reference inspection.
