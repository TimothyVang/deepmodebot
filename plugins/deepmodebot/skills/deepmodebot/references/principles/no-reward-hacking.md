# no-reward-hacking

Group: verification. When: writing code or tests, fixing bugs, iterating against any check/benchmark/gate, building UIs/APIs/CLIs/ML/3D, or declaring work done.
- **Rule.** Satisfy the operator's true goal rather than gaming the proxy metric across **all** engineering domains (Goodhart's Law: once a test, benchmark, linter, or scalar gate becomes the optimization target, shortcuts score 100% while failing the real requirement).
- **Freeze tests, strictness & shell flags.** Never delete/tautologize assertions (`assert True`), add `.skip`/`--no-cov`/`--passWithNoTests`/`continue-on-error: true`, disable `tsconfig` `strict`, lower coverage or `[0, 1]` bounds (`--cov-fail-under < 50`, `--min-iou < 0.50`), or branch on `PYTEST_CURRENT_TEST`/`JEST_WORKER_ID` in production code. Lock gates first (`reward_guard.py lock-contract --goal ... --verify-cmd ...`).
- **Universal sealed judge (`run-judge`).** On code/API/CLI tasks (no images or DGX required), `reward_guard.py run-judge` runs `--verify-cmd` itself, captures `git diff`, and audits both inside a sealed `omp -p --no-tools` prosecutor signed with an outer-supervisor Ed25519 key. On UI/2D/3D tasks, it attaches locked references + owned headless Blender renders (`.glb`/`.fbx`/`.blend`/`.obj`) and verifies upstream Ed25519 receipts when required.
- **Outer-supervisor ownership (`loop.py`).** `loop.py` (`forbid_reward_hacks: true`, `reward_judge: true` or `reward_artifacts`) freezes protected files and guardrail configs (`exit 4` on mutation), holds an ephemeral Ed25519 key in parent RAM, and runs `.scratch/` scans + `run-judge` outside the builder turn in a private `realpath`-verified holdout.
- **Anti-patterns.** Hardcoding test fixture inputs or `PYTEST_CURRENT_TEST` branches in `src/`; mocking the system under test; deleting failing `assert` lines; lowering `--cov-fail-under` or `--min-*`; letting the builder own the final completion gate.
