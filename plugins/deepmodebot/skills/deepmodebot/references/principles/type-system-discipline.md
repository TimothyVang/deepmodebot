# type-system-discipline

Group: architecture. When: designing types, reviewing a signature, writing any statically-typed code.
- **Rule.** Make the compiler reject impossible states, mismatched primitives, and unhandled variants. Define errors and special cases out of existence rather than multiplying handlers.
- **Checks.** Brand semantic primitives (`UserId` vs `OrderId`) via verifying type guards (`input is UserId`), never via `as`. Model invariants constructively so illegal values cannot be built (`[T, ...T[]]` for non-empty, `start` + `duration` for ranges) while keeping `T[]` when operations stay total. Use `unknown` over `any`; parse external data with the repo's schema library (`z.infer` etc.) before hand-writing guards, stopping `Record<string, unknown>` at the boundary. Narrow in order: discriminant switch > `in` > `typeof`/`instanceof` > verifying type guard > `as` (last resort). Prefer `satisfies` over `as`, derive types (`Pick`/`Omit`/`ReturnType`/`typeof`) from schemas, and enforce exhaustiveness with `const _exhaustive: never = x;`.
- **Anti-patterns.** Hand-maintained parallel types; `as any` / `as unknown as` casts; lying type guards that do not verify the claim; optional-field bags instead of discriminated unions.
