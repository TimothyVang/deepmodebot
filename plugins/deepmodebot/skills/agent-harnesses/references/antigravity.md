# Google Antigravity harness reference

Read when deepmodebot runs inside Google Antigravity (the Antigravity App, Antigravity CLI `agy`, Antigravity IDE or IDE extensions, the Python SDK, or an ACP client driving `agy acp`), or when you must translate a deepmodebot instruction written for omp into Antigravity tools, files, and flags.

Checked: 2026-11-13 against [antigravity.google/docs](https://antigravity.google/docs/overview) (canonical docs site; index at [llms.txt](https://antigravity.google/llms.txt)).

## Surfaces, auth, and models

- Surfaces share one customization model across the desktop **Antigravity App** (`~/.gemini/antigravity`), **Antigravity CLI** `agy` (`~/.gemini/antigravity-cli`, settings in `~/.gemini/antigravity-cli/settings.json`), **Antigravity IDE** (`~/.gemini/antigravity-ide`), **IDE extensions** (VS Code, JetBrains, Visual Studio, Zed, Xcode), and the Python **Antigravity SDK** ([overview](https://antigravity.google/docs/overview), [extensions](https://antigravity.google/docs/ide/extensions), [SDK](https://antigravity.google/docs/sdk/overview)).
- Gemini CLI stopped serving Google AI Pro, Ultra, and free accounts on 2026-06-18; those tiers moved to `agy` ([migration](https://antigravity.google/docs/cli/gcli-migration)).
- Auth: cached Google OAuth sign-in from interactive `agy` or `agy acp --login`, GCP project (`gcp` in `settings.json`), or `GEMINI_API_KEY` with `"modelProvider": "gemini"` ([install](https://antigravity.google/docs/install), [reference](https://antigravity.google/docs/cli/reference), [ACP](https://antigravity.google/docs/cli/acp)). Headless `agy -p` reuses cached credentials and exits immediately with `authentication required` if unauthenticated instead of opening a browser ([headless](https://antigravity.google/docs/cli/headless)).
- Models and effort: `agy models` lists available slugs; `--model <slug>` or `/model` selects one, and an unknown slug fails with exit `1` and `status: "ERROR"` ([headless](https://antigravity.google/docs/cli/headless), [reference](https://antigravity.google/docs/cli/reference)). `--effort low|medium|high|xhigh|max` or `/effort` sets reasoning effort; `agy agents` lists agents and `--agent <name>` selects the main agent ([reference](https://antigravity.google/docs/cli/reference)).

## Discovery scopes, rules, and manifests

| Location | Scope |
| - | - |
| `.agents/` in cwd and parents up to repo root (`.git`); legacy `.agent/`, `_agents/`, `_agent/` | Workspace (`skills/`, `rules/`, `agents/`, `plugins/`, `hooks.json`, `mcp_config.json`, manifests) |
| `AGENTS.md` and `GEMINI.md` in cwd and parents up to repo root | Workspace instructions (always on; subfolders below cwd are not scanned) |
| `~/.gemini/config/` plus `~/.gemini/AGENTS.md` and `~/.gemini/GEMINI.md` | Personal global scope shared by App, CLI `agy`, and IDE |
| `.gemini/config.json` `{"personal_customization_dir": "people/{user}"}` | Shared-repo personal dir (`people/<user>/.agents/`, `USER` or Windows `USERNAME`) |
| `~/.gemini/antigravity-cli/skills/` and `~/.gemini/skills/` | **CLI-only** skill dirs (ignored by App; outrank workspace skills in `agy`) |

Source: [customization-discovery](https://antigravity.google/docs/customization-discovery).

- `.gemini/skills/` in a workspace is **not** read; use `.agents/skills/` ([migration](https://antigravity.google/docs/cli/gcli-migration)). Additional workspace roots come from CLI `--add-dir <path>` or `/add-dir` ([customization-discovery](https://antigravity.google/docs/customization-discovery)).
- One-level scan depth: `skills/<name>/SKILL.md`, `rules/<name>.md`, and `agents/<name>.md` (or `agents/<name>/agent.md`). Deeper nesting (`skills/group/x/SKILL.md`) is skipped unless pointed to by a discovery manifest ([customization-discovery](https://antigravity.google/docs/customization-discovery)).
- Discovery manifests: `skills.json`, `rules.json`, `agents.json`, and `plugins.json` inside `.agents/` or `~/.gemini/config/` declare `entries` (`[{ path, include_only?, exclude? }]`), `inherits`, and top-level `exclude` (`string[]`). Lists take exact names (no wildcards), and `~` is not expanded in manifest paths ([customization-discovery](https://antigravity.google/docs/customization-discovery)).
- Priority order for skills and custom agents (first wins): CLI-only `~/.gemini/antigravity-cli/skills/` and `~/.gemini/skills/` (in `agy` only, bypassing manifest `exclude` lists) > repo `personal_customization_dir` > workspace `.agents/` and manifests > personal `~/.gemini/config/` and manifests > built-ins ([customization-discovery](https://antigravity.google/docs/customization-discovery), [skills](https://antigravity.google/docs/skills)).
- Rules never replace each other: every matching rule loads, deduplicated by resolved file path ([customization-discovery](https://antigravity.google/docs/customization-discovery)).
- `AGENTS.md` and `GEMINI.md` (plus plugin `rules/AGENTS.md`) are plain Markdown and always active. Named `rules/<name>.md` files require YAML frontmatter `trigger`: `always_on`, `model_decision` (needs `description`), `glob` (needs `globs` as a **comma-separated string** `"**/*.ts, **/*.tsx"`, not a YAML array), or `manual` (`@<name>`) ([rules](https://antigravity.google/docs/rules), [build-plugins](https://antigravity.google/docs/build-plugins)).
- Reload: rules and skills re-read before each turn; in interactive `agy`, run `/skills reload` (or start a new session) to refresh slash-command completions ([customization-discovery](https://antigravity.google/docs/customization-discovery), [skills](https://antigravity.google/docs/skills)).

## Skills and plugins

- Skills follow Agent Skills (`<name>/SKILL.md` with `name` and `description`); unknown frontmatter keys (such as Claude Code's `hooks:`) are ignored cleanly. Every discovered skill registers `/<skill-name>` in chat, while plugin skills carry internal ID `<plugin>:<skill>` so they do not collide with workspace skills ([skills](https://antigravity.google/docs/skills), [plugins](https://antigravity.google/docs/plugins), [customization-discovery](https://antigravity.google/docs/customization-discovery)).
- Plugin manifests: `<plugin-root>/.antigravity-plugin/plugin.json` or `<plugin-root>/plugin.json`. `.antigravity-plugin/plugin.json` takes precedence over root `plugin.json` so multi-harness plugins can coexist with `.claude-plugin/plugin.json` ([build-plugins](https://antigravity.google/docs/build-plugins)).
- Schema `https://antigravity.google/schemas/v1/plugin.json` enforces `additionalProperties: false` with keys `$schema`, `name` (required, kebab-case), `displayName`, `description`, `version`, `disabled`, `logo`, `suggestedPrompts` (max 3), `skills` (extra relative skill dir path or array), `author`, `homepage`, `repository`, `license`, `keywords`, `extensions` ([build-plugins](https://antigravity.google/docs/build-plugins)). Claude `commands/*.md` files are ignored.
- Install locations: `~/.gemini/config/plugins/<name>/` (global, staged by `agy plugin install` and shared by App and CLI) or `.agents/plugins/<name>/` (workspace) ([plugins](https://antigravity.google/docs/plugins), [build-plugins](https://antigravity.google/docs/build-plugins)).
- CLI management: `agy plugin install <name>[@antigravity-plugins-official]`, `agy plugin install https://github.com/<owner>/<repo>` (or `https://github.com/<owner>/<repo>/tree/<branch>/<subdir>` when `plugin.json` lives in a subfolder, e.g. `agy plugin install ./plugins/deepmodebot` from a clone), `agy plugin install <local-path>`, `agy plugin list [--json]`, `enable`, `disable`, `uninstall`, `validate [--strict] <dir>`, and `import [gemini|claude|<path>]`. Interactive TUI: `/plugin` (alias `/plugins`) ([plugins](https://antigravity.google/docs/plugins), [build-plugins](https://antigravity.google/docs/build-plugins), [marketplace](https://antigravity.google/docs/marketplace)).
- Only `antigravity-plugins-official` is accepted after `@`; third-party repos install directly from a GitHub URL or local path ([marketplace](https://antigravity.google/docs/marketplace)).
- Path variables: `${PLUGIN_ROOT}` (read-only `~/.gemini/config/plugins/<name>`, replaced on update) and `${PLUGIN_DATA}` (persistent writable dir outside the workspace). Antigravity expands them in `mcp_config.json` (`args`, `cwd`, custom `env`) and exports `PLUGIN_ROOT` and `PLUGIN_DATA` into plugin MCP servers and plugin command hooks ([build-plugins](https://antigravity.google/docs/build-plugins)).
- Do not redeclare `PLUGIN_ROOT` or `PLUGIN_DATA` inside `mcp_config.json` `env`, and use `./scripts/...` in `hooks.json` because hook `cwd` is already `<plugin-root>` ([build-plugins](https://antigravity.google/docs/build-plugins)).

## Custom subagents and orchestrators

- Subagent tools: `invoke_subagent` spawns concurrent child sessions with clean context (`Workspace`: `inherit` default, `branch` isolated git worktree, `share` shared working copy); `define_subagent` defines a session-scoped subagent; `send_message` (`Recipient`, `Message`) wakes an `Idle` subagent with its history intact; `manage_subagents` supports `list`, `kill`, and `kill_all` ([subagents](https://antigravity.google/docs/subagents)).
- Built-in subagents: `research` (codebase exploration), `browser` (UI verification, screenshots, console and network inspection; `/browser`), and `self` (clone of the calling agent) ([subagents](https://antigravity.google/docs/subagents)).
- Custom subagent files live in `.agents/agents/<name>.md` (or `<name>/agent.md`), `~/.gemini/config/agents/`, or plugin `agents/<name>.md` / `agents/<name>/agent.md`. In multi-harness plugins shared with omp or Claude Code, use `agents/<name>/agent.md` so Antigravity loads the subagent while omp and Claude Code (`agents/*.md`) ignore it and keep their own built-ins.
  - Frontmatter: `name` and `description` (required), `tools` (allowlist; `send_message` is always included), `mainAgent` (default `true`; selectable via `agy --agent <name>` or `/agents`), `subagent` (default `true`), `model` (`inherit` default, `flash_lite`, `flash`, `pro`), `commandExecutionPolicy` (`sandbox` default, `off`, `auto`, `eager`), `mcpServers`, `skills`, `plugins`, `inheritMcp` (`true`), and `inheritCustomizations` (`true`) ([subagents](https://antigravity.google/docs/subagents), [build-plugins](https://antigravity.google/docs/build-plugins)).
- **Tool-name hang warning:** unmapped or misspelled names in `tools:` frontmatter can cause the subagent process to hang during execution. List only verified Antigravity tool names (or omit `tools:` to inherit the default set) ([subagents](https://antigravity.google/docs/subagents)).
- Nesting is capped at 10 levels. Lifecycle states are `Running`, `Idle` (zero cost until messaged), and `Killed` (`kill` deletes temporary `branch`/`share` worktrees while retaining the JSONL transcript). CLI controls: `/agents`, `Alt+J` (jump to subagent awaiting approval), `Ctrl+K` (fast-path approve), `@<subagent>` (direct message), `/tasks` (`manage_task` for background shell jobs) ([subagents](https://antigravity.google/docs/subagents)).
- Native orchestrators: `/boost` (iterative `Orchestrator` -> `DeepCoder`/`DeepInvestigator` -> workers for hard problems; paid plans, [boost](https://antigravity.google/docs/boost)) and `/swarm` (coordinator + named workers + verifier on a shared `@mention` board where waiting workers cost zero tokens; AI Pro/Ultra, [swarm](https://antigravity.google/docs/swarm)).
  - Also `/teamwork` (scoping interview + milestone gates with Critic, Challenger, and Auditor; paid plans, [teamwork](https://antigravity.google/docs/teamwork)) and `/run-workflow` (Python-scripted staged/parallel agent workflows with structured outputs, [dynamic-workflows](https://antigravity.google/docs/dynamic-workflows)).

## Lifecycle hooks

- Locations: `.agents/hooks.json`, `~/.gemini/config/hooks.json`, or `<plugin-root>/hooks.json` (`~/.gemini/antigravity-cli/settings.json` hooks are not loaded). Inspect loaded hooks with `/hooks` ([hooks](https://antigravity.google/docs/hooks), [build-plugins](https://antigravity.google/docs/build-plugins)).
- Schema: top-level object mapping `<hook-group-name>` to `{ "enabled"?: true, "<Event>": ... }` (not Claude Code's `"hooks": { ... }` wrapper) ([hooks](https://antigravity.google/docs/hooks)).
- Six events: `PreToolUse` and `PostToolUse` take grouped matcher arrays `[{ "matcher": "<tool-regex>", "hooks": [{ "type": "command", "command": "...", "timeout": 30 }] }]`; `SessionStart`, `PreInvocation`, `PostInvocation`, and `Stop` take flat handler arrays `[{ "type": "command", "command": "...", "timeout": 30 }]` (matchers are ignored) ([hooks](https://antigravity.google/docs/hooks)).
- Shell and cwd: only synchronous `type: "command"` is supported, invoked via `sh -c` on Unix and `cmd /c` on Windows with process `cwd` set to the folder holding `hooks.json` (`<plugin-root>` for plugins). Prefer `node ./scripts/<handler>.mjs` over `.sh` for cross-platform plugins ([hooks](https://antigravity.google/docs/hooks), [build-plugins](https://antigravity.google/docs/build-plugins)).
- camelCase JSON stdin/stdout: stdin always includes `conversationId`, `workspacePaths`, `transcriptPath`, `artifactDirectoryPath`, `modelName`, `lastUserInput`, `hookEventName`, and `cwd` (the agent's workspace cwd) ([hooks](https://antigravity.google/docs/hooks)).
  - `PreToolUse` stdin adds `toolCall: { id, name, args }` and `stepIdx`; stdout returns `{ "decision": "allow" | "auto_approve" | "deny" | "ask" | "force_ask" | "deny_unless_prior_grant", "reason"?: "...", "overwrite"?: {...}, "permissionOverrides"?: {...} }` (`overwrite` shallow-merges top-level `toolCall.args`).
  - `PostToolUse` stdin provides `toolCall` and `error` (not tool output); stdout returns `{}`.
  - `SessionStart`, `PreInvocation`, and `PostInvocation` stdout supports `injectSteps` (`systemMessage`, `userMessage`, `errorMessage`) plus `terminationBehavior` (`"terminate"` in Pre/Post, `"force_continue"` in Post).
  - `Stop` stdin adds `executionNum`, `terminationReason`, `fullyIdle`, and `continuationActive`; stdout `{"decision": "continue", "reason": "..."}` resumes work (check `continuationActive` first to avoid infinite loops) ([hooks](https://antigravity.google/docs/hooks)).
- **Exit `0` required (fail-open rule):** hook commands must exit `0` and emit valid JSON on stdout. **Any non-zero exit code is logged as a hook error and ignored, failing open** — the opposite of Claude Code's blocking exit `2` ([hooks](https://antigravity.google/docs/hooks)).

## MCP

- Config files: `~/.gemini/config/mcp_config.json`, `.agents/mcp_config.json`, and `<plugin-root>/mcp_config.json` under root key `mcpServers`. Interactive manager: `/mcp`. Plugin servers are namespaced `<plugin-name>_<server-key>` ([mcp](https://antigravity.google/docs/mcp), [build-plugins](https://antigravity.google/docs/build-plugins)).
- Transports and timeouts: local `stdio` (`command`, `args`, `env`, `cwd`) or remote **Streamable HTTP only** (`serverUrl` or `url`, `headers`; legacy HTTP+SSE and `httpUrl` are unsupported in `mcp_config.json`). `timeoutSeconds` defaults to `300`s connect and `180`s per tool call; a positive integer overrides both (e.g. `600`), and `-1` disables timeouts ([mcp](https://antigravity.google/docs/mcp)).
- Lazy vs eager tool loading: MCP tools lazy-load by default — schemas cache to `<app-data-dir>/mcp/<serverName>/<toolName>.json` and the agent calls them through `call_mcp_tool` (`ServerName`, `ToolName`, `Arguments`). Setting `"tools": { "<tool>": { "eager": true, "background"?: "off"|"always" } }` registers `mcp_<serverName>_<toolName>` directly in tool declarations at higher per-turn token cost. Filter tools with `enabledTools`, `disabledTools`, or `disabled` ([mcp](https://antigravity.google/docs/mcp)).
- Auth and `variables` trap: supports `authProviderType: "google_credentials"` (ADC) and OAuth 2.0 PKCE via CIMD, DCR, or manual `oauth` (`redirect_uri` `https://antigravity.google/oauth-callback`; tokens in `~/.gemini/antigravity/mcp_oauth_tokens.json`). Declaring `mcpServers.<server>.variables` causes `agy plugin install` to install the plugin **disabled** until the user fills in every variable in `/plugin` or App Customizations ([mcp](https://antigravity.google/docs/mcp), [build-plugins](https://antigravity.google/docs/build-plugins)).

## Headless mode and ACP

- `agy -p "<prompt>"` (`--print` / `--prompt`) writes the response to `stdout` and diagnostics, errors, and permission notices to `stderr`. `--output-format text|json|stream-json`: `json` emits `{ conversation_id, status, response, error?, duration_seconds, num_turns, structured_output?, json_schema?, usage }`; `stream-json` emits NDJSON `init`, `step_update`, and `result`. `--json-schema '<schema-or-file>'` enforces structured output (`structured_output`) ([headless](https://antigravity.google/docs/cli/headless), [reference](https://antigravity.google/docs/cli/reference)).
- Multi-turn streaming: `agy --input-format stream-json --output-format stream-json` reads `{"event":"user","message":{"content":"..."}}` lines on `stdin` (omit `-p`; CLI-only slash commands like `/model` exit `2`; `usage`, `num_turns`, and `duration_seconds` are cumulative while `response` is per-turn; close `stdin` to exit `0`). Resume with `-c`/`--continue` or `--conversation <id>`; bound wall time with `--print-timeout 15m` (`0s` = unlimited); `--disable-slash-commands` treats leading `/` literally ([headless](https://antigravity.google/docs/cli/headless)).
- **Soft-deny headless trap:** in `agy -p`, actions matching an `Ask` rule are soft-denied with a stderr notice while the turn continues and can still exit `0`. Pre-allow required actions in `~/.gemini/antigravity-cli/settings.json` `permissions.allow`, or pass `--dangerously-skip-permissions` only inside an isolated container or VM ([headless](https://antigravity.google/docs/cli/headless), [permissions](https://antigravity.google/docs/permissions)).
- Native ACP server: `agy acp [flags]` runs an Agent Client Protocol agent over stdio JSON-RPC for Zed, JetBrains, VS Code, Xcode, and `acpx`. Authenticate once via interactive `agy` or `agy acp --login` ([ACP](https://antigravity.google/docs/cli/acp)).

## Sandbox and permissions

- OS sandbox: Linux kernel namespaces, macOS `sandbox-exec` (Seatbelt), and Windows AppContainer process security environments (requires Windows 11 24H2 with the August 2026 update; folders outside the user profile stay readable on Windows). The sandbox blocks `~/.ssh` and `.env`, and blocks network access except domains allowed via `read_url(...)`. On unsupported hosts (`v1.4.4+`), `--sandbox` / `enableTerminalSandbox` is a no-op and `proceed-in-sandbox` falls back to `request-review` ([sandbox](https://antigravity.google/docs/sandbox)).
- Presets and CLI settings: App presets are `Request Review` (sandbox off, ask), `Default` (sandbox on, allow inside / ask outside), `Auto` (sandbox on, safe outside actions auto-approved; personal accounts only), and `Turbo` (sandbox off, unrestricted) ([sandbox](https://antigravity.google/docs/sandbox), [permissions](https://antigravity.google/docs/permissions)).
- CLI `~/.gemini/antigravity-cli/settings.json` sets `agentMode` (`""`, `"accept-edits"`, `"auto"`, `"plan"`, or `--mode`), `toolPermission` (`"request-review"`, `"proceed-in-sandbox"`, `"always-proceed"`, `"strict"`), `enableTerminalSandbox` (`false` unless `auto` or `--sandbox`), and `allowNonWorkspaceAccess` (`false` default) ([reference](https://antigravity.google/docs/cli/reference)).
- Fine-grained rules evaluate `Deny > Ask > Allow` with `action(target)`: `read_file(...)`, `write_file(...)` (implies `read_file`), `read_url(domain)`, `execute_url(domain)` (browser navigation; `read_url` does not grant `execute_url`; `localhost:port` isolated per port), `download_url(domain)`, `command(prefix)` or `command(regex:pattern)`, `unsandboxed(...)`, and `mcp(server/tool)` or `mcp(server/*)` (unconfigured MCP tools default to `Ask`) ([permissions](https://antigravity.google/docs/permissions)).
- Shell subcommand/substitution syntax (`$(...)`, backticks, brace expansion, `git -c core.pager=...`, unparseable Windows shell lines) disables prefix matching and requires an exact full-line or `regex:` rule; Windows file rules strip drive letters (`C:`) and normalize `\` to `/` ([permissions](https://antigravity.google/docs/permissions)).

## Containing writes to the project root

- Keep workspace roots scoped to the repository (`allowNonWorkspaceAccess: false`, no outside `--add-dir`), enable `--sandbox` / `enableTerminalSandbox: true` where supported, and export `TMPDIR`, `TMP`, and `TEMP` to `<repo>/.scratch/tmp` in shell calls ([permissions](https://antigravity.google/docs/permissions), [sandbox](https://antigravity.google/docs/sandbox)).
- Path-blocking hook: `PreToolUse` with matcher `write_file|edit_file|write_to_file|replace_file_content|multi_replace_file_content` (surface/model variants pass `args.Path` on `write_file`/`edit_file` and `args.TargetFile` on `write_to_file`/`replace_file_content`/`multi_replace_file_content`). Normalize Windows drive letters and backslashes, compare against the workspace root, main checkout `.worktrees/`, `.deepmodebot.json` `extraWriteRoots`, and `artifactDirectoryPath`, and exit `0` with `{"decision":"deny","reason":"..."}` on violations ([hooks](https://antigravity.google/docs/hooks)).
- Antigravity's own state outside the repo (not yours; never clean or report it as a leak): `~/.gemini/config/`, `~/.gemini/antigravity/`, `~/.gemini/antigravity-cli/`, `~/.gemini/antigravity-ide/` (including `<app-data-dir>/brain/<conversationId>/` artifacts and `transcript.jsonl`, `<app-data-dir>/mcp/` cached tool schemas, and `mcp_oauth_tokens.json`), plus `${PLUGIN_DATA}` ([customization-discovery](https://antigravity.google/docs/customization-discovery), [hooks](https://antigravity.google/docs/hooks), [mcp](https://antigravity.google/docs/mcp)).

## Traps for deepmodebot

- Claude `commands/*.md` files do not load in Antigravity. deepmodebot's `.antigravity-plugin/plugin.json` adds `./.antigravity-plugin/skills` (`/deep`, `/tournament`, `/review-pr`, `/land-pr`, `/pr-thread`) alongside `skills/` (which already provides `/contribute` and `/project-brief`), so slash commands work directly without a `/deepmodebot:` prefix.
- `skill://deepmodebot/...` URIs do not resolve natively: read files from `~/.gemini/config/plugins/deepmodebot/skills/<name>/` (or `.agents/plugins/deepmodebot/skills/<name>/`), or resolve them via `omp_resolve` on deepmodebot's bundled `omp` MCP server when omp is installed.
- Bundled containment & auto-map guard (`hooks.json` -> `node ./scripts/antigravity-guard.mjs`): `PreInvocation` marks sessions whose `lastUserInput` starts with `/deep`, `/deepmodebot`, `/tournament`, `/review-pr`, `/land-pr`, `/pr-thread`, `/contribute`, or `/project-brief` (persisting marks in `PLUGIN_DATA` or `~/.gemini/antigravity/deepmodebot-guard`), and inside git repos auto-injects a fast offline git-only `workspace-map` overview (`--fast --offline --no-orca`, `<= 1200 B`, writing `<main-checkout>/.scratch/workspace-map.db`; skipped on `/review-pr` when no DB exists) via `injectSteps`.
  - `PreToolUse` denies file-tool writes outside the project root, main `.worktrees/`, `.deepmodebot.json` `extraWriteRoots`, and `artifactDirectoryPath`, always exiting `0` so it never fails open. Shell commands still require discipline.
- Bundled subagents (`agents/scout/agent.md`, `agents/reviewer/agent.md`, `agents/security-reviewer/agent.md`): omp `task` maps to `invoke_subagent` (`SubagentName: "scout" | "reviewer" | "security-reviewer"` or built-in `research` / `self`; keep `Workspace: "inherit"` with exclusive file ownership unless an isolated worktree is intended). Keep `tools:` lists restricted to verified Antigravity tool names so subagents never hang.
- Bundled `omp` MCP bridge (`mcp_config.json` -> `node ./scripts/omp-mcp-server.mjs`, namespaced `deepmodebot_omp`, `timeoutSeconds: 600`): exposes `omp_run` (`omp -p --mode json` with stdin prompt delivery and per-call `timeoutSeconds` + process-tree kill), `omp_task` (concurrent dispatch; `scout` defaults to `@smol`/`medium`, `reviewer` to `@slow`, optional `thinking`), and `omp_resolve` while stripping `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `OPENAI_API_KEY`, and `CODEX_API_KEY` by default so omp stays on its subscription login.
  - Unconfigured MCP tools default to `Ask` in Antigravity; add `mcp(deepmodebot_omp/*)` to `permissions.allow` before unattended `agy -p` runs so calls are not soft-denied.
- CLI-only `~/.gemini/skills/` trap: stale copies in `~/.gemini/skills/` or `~/.gemini/antigravity-cli/skills/` outrank workspace `.agents/skills/` and plugins in `agy` while staying invisible in Antigravity App. Install via `agy plugin install` (`~/.gemini/config/plugins/`) or `.agents/skills/` instead.
- Project verify skills belong in `.agents/skills/verify-<app>/SKILL.md` (mirroring `.omp/skills/verify-<app>/`) so Antigravity App, CLI, and IDE all discover them.
- omp `todo` -> task artifact in Antigravity App or a repo checklist in CLI; omp `ask` -> `ask_question` interactively, or decide and log the assumption in `agy -p`.
